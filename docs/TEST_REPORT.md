单元测试覆盖：正文噪声与隐藏/敏感节点排除、标题/代码/表格/链接、列表内代码、长文本分块、中英文检索及预算、源定位校验与歧义拒绝、访问拦截识别、可信提示与不可信正文隔离、真实引用 ID 限制、历史裁剪、协议地址验证、SSE 跨字节与换行边界、认证/限流/404/500、格式损坏、网络失败、取消、可选温度、IndexedDB 会话隔离与独立清理。

10 项端到端场景：

1. 实际加载扩展、提取页面、流式回答、代码高亮、LaTeX、点击引用定位。
2. 连续追问带有限历史，停止生成后恢复交互。
3. 原网页划词解释卡片，且网页的恶意全局按钮 CSS 不影响 Shadow DOM 样式。
4. 标签页切换、SPA 导航、返回原页时会话隔离与恢复。
5. 认证错误可继续提问，模型 HTML、脚本链接、虚构引用不会成为可执行内容或真实来源。
6. 通过真实 content script 尝试读取密钥存储被拒绝；设置保存与删除历史确实反映到数据库。
7. 长文档普通问答遵守检索预算；全文概括经显式提示允许后分批发送，覆盖最终章节的唯一标记。
8. 浏览器受限页面明确报错；同 URL 内容更新停用旧上下文，经主动重新读取恢复。
9. 网页划词入口实际打开原生侧边栏，以 `chrome.runtime.getContexts({contextTypes:['SIDE_PANEL']})` 验证。
10. 不增加任何主机权限的临时扩展，在全新浏览器配置中通过 X11 原生按键触发真实工具栏动作：先验证 URL 因未授权被隐藏，再验证临时授权、已打开侧边栏恢复、另一未授权标签页恢复，以及持续主机权限仍为空。

端到端测试使用真实 Chromium 扩展 API，不模拟 chrome 对象。为可重复验证模型协议，测试连接本机 HTTP 模型夹具服务；只在临时扩展副本中增加 loopback 主机权限，生产 manifest 未增加该权限。真实服务验证使用用户本地配置，仅在内存/浏览器会话保存密钥；临时浏览器配置在结束后删除。

新增工具栏测试没有添加 loopback 或其他主机权限，仅添加 `_execute_action` 快捷键以触发与点击图标相同的浏览器动作。它需要 Linux X11、Python 3、libX11、libXtst，可在 Xvfb 中运行。v1.0.0 在该测试中原生侧边栏已打开，但网页 URL 仍为 undefined；v1.0.1 能授予临时权限并完成正文读取。原有预授权的 UI 测试无法覆盖这个入口缺陷，因此保留原测试并新增独立权限回归。

# AI Reading Copilot · 浏览器智能文档阅读助手

右键打开当前页阅读助手，选中文字即可用小浮窗解释术语、代码和公式；需要时进入侧边栏连续问答，并通过真实片段引用回到原文。面向个人和小范围朋友分享，使用各自的模型 API Key，无账号、无强制后端。

## 下载

- [下载 Chrome / Edge 扩展安装包](https://github.com/a1574727816-max/ai-reading-copilot/releases/latest/download/ai-reading-copilot-1.1.0-extension.zip)
- [查看 Release、源码包和 SHA-256 校验文件](https://github.com/a1574727816-max/ai-reading-copilot/releases/latest)

日常使用请选择名称以 `extension.zip` 结尾的附件，解压后加载到浏览器。GitHub 自动提供的 “Source code” 是源码，需要自行构建。安装包不含任何个人密钥，每位使用者在设置中填写自己的 API Key。

## 快速安装（Windows / Chrome / Edge）

已有发布包时无需安装 Node.js：

1. 解压 `release/ai-reading-copilot-1.1.0-extension.zip` 到一个固定文件夹，不要直接打开 ZIP。
2. Chrome 打开 `chrome://extensions`；Edge 打开 `edge://extensions`。
3. 开启“开发者模式”，选择“加载已解压的扩展程序”，选中包含 `manifest.json` 的解压目录。源码构建后可直接选择本项目的 `dist` 目录。
4. 把阅读助手固定到工具栏，打开扩展“选项”配置模型。
5. 回到普通 HTTP/HTTPS 文档网页，在空白处右键，点击“打开阅读助手”。助手读取当前文档并显示简短提示，工具栏图标出现 `ON`；此时不会打开右侧栏或调用模型。
6. 选中文字，自动弹出“解释概念 / 结合上下文 / 举例说明 / 向 AI 提问”小浮窗。点击解释操作后才调用模型；首次发送提示可直接在浮窗确认。
7. 再次在空白处右键，点击“关闭阅读助手”即可停用当前页。浮窗里的“关闭”仅收起本次卡片。
8. 需要连续问答时，主动点击浮窗里的“向 AI 提问”或“详细解释 / 继续提问”，再进入右侧栏；点击“原文”引用可定位网页。

更新扩展：用新文件替换原解压目录，回到扩展管理页点击“重新加载”，再刷新文档网页。保留原目录可保留扩展身份与本地设置。不要把密钥文件放进扩展目录或分享包。

v1.1.0 将默认交互改为“右键启用 → 读取文档 → 划词小浮窗”。工具栏图标与 `Alt+Shift+R` 同样切换当前页开关；右侧问答栏保留为主动入口。更新后无需卸载。

## DeepSeek 与兼容服务配置

1. 服务类型选择“DeepSeek 官方”，Base URL 默认 `https://api.deepseek.com`。
2. 输入自己的 API Key。默认仅在当前浏览器会话保存；选择“保存在这台设备”时，会提示本机存储的风险。
3. 点击“获取模型”，从服务实际返回的列表选择模型，也可手动填写模型 ID。模型名不会固定在代码中。
4. 点击“测试真实连接”，再点击“保存模型与偏好”。连接测试会产生一条极短的生成请求。
5. 自定义服务选择“OpenAI-compatible”，填写服务商提供的 Base URL（可含 `/v1`）、模型 ID 和密钥。默认使用 `/models` 与 `/chat/completions`；列表不兼容时手填 ID。不支持温度的模型可清空温度输入框。

模型服务需要按域名授予访问权限；这不等于授权插件读取所有网页。仅支持 HTTPS，运行在 `localhost` / `127.0.0.1` / `::1` 的本机服务可以使用 HTTP。兼容服务必须支持文本 Chat Completions；专有协议需新增 Provider Adapter。

## 网页授权与使用

- 空白处右键菜单根据当前页状态显示“打开阅读助手”或“关闭阅读助手”；点击工具栏图标或 `Alt+Shift+R` 也可切换。快捷键可在浏览器扩展快捷键页面调整。
- 无临时授权时，侧边栏提供“授权当前网站并读取”，仅向当前网站申请持续访问权限。
- 持续授权允许后续访问该站点时注入工具，但仍需主动打开当前页助手才显示划词浮窗。可以在设置中关闭划词浮层、撤销站点授权，或把域名加入禁用列表。
- 开关按页面与标签页隔离，刷新或跳转到另一份文档后需要重新打开；同一页正文更新会使旧缓存失效，下次解释读取新内容。
- 小浮窗解释会从当前文档检索相关片段；复杂问题可点击“向 AI 提问 / 继续提问”进入侧边栏。
- 浏览器内部页面、商店页面、内置 PDF 阅读器等受限页面不能注入；不会绕过浏览器边界。

侧边栏有自动、选区、当前文档、通用知识四种上下文模式。当前文档指当前网页，不自动抓取左侧目录里的其他网页。

## 已实现的 V1 功能

- 语义正文提取、Readability 回退、标题层级、段落/列表、代码、表格、链接与可提取公式。
- 基于标题与段落分块、中英文关键词 BM25 检索、邻近片段补充、原文上下文与历史长度限制。
- 术语和选区解释、通俗解释、举例、深入追问；小型卡片可直接在原网页显示。
- 真实模型调用、流式输出、停止、重新生成、复制答案与代码、认证/限流/网络/格式错误提示。
- Markdown、代码高亮、LaTeX；模型 HTML 不执行，危险链接与远程图片不直接渲染。
- 仅接受实际提供给模型的片段 ID；引用可查看片段、滚动定位、短暂覆盖高亮。定位前校验原文，无法唯一定位就报错。
- 标签页与文档版本隔离、SPA URL/正文变化失效、主动重新读取、当前页内解析缓存。
- 长文档问答只发送检索片段；全文概括逐批分析全部已提取文字，再有界汇总。完整发送默认关闭，可以在提示中仅允许本次概括。
- IndexedDB 本地文档缓存和历史、恢复/新建/清空/删除会话，文档缓存与历史单独清理，最多缓存最近 30 份文档。
- 本机与会话两种密钥保存方式、阅读偏好、明暗主题、禁用域名与全部本地数据重置。

## 从源码构建

需要 Node.js 22.12+（建议 Node.js 24 LTS）和 npm。所有命令在项目根目录执行，Windows PowerShell 同样可用。

```sh
npm ci
npm run check
npm run test:e2e
npm run package
```

首次运行浏览器测试前：

```sh
npx playwright install chromium
```

Linux 上可用 `xvfb-run -a npm run test:e2e` 同时运行真实工具栏权限回归测试。该测试需要 Xvfb、Python 3、libX11 与 libXtst，通过原生工具栏动作快捷键验证完全未授权网页的右键开关、工具栏动作、首次发送、关闭取消与页面隔离；普通无显示环境下会明确跳过该项，其他测试正常运行。

`npm run dev` 监听并更新 `dist`，改动后需要在浏览器中重新加载扩展并刷新网页。开发构建同样不使用远程脚本或 HMR 注入。

| 命令 | 用途 |
| --- | --- |
| `npm run typecheck` | TypeScript 检查 |
| `npm test` | 文档、检索、引用、模型协议、存储单元测试 |
| `npm run test:e2e` | Chromium 中加载真实扩展，连接本机测试模型服务 |
| `npm run build` | 生成可加载的 `dist` |
| `npm run package` | 构建并生成扩展 ZIP、源码 ZIP 与 SHA-256 |
| `node scripts/verify-release.mjs` | 检查构建入口、权限和本地测试密钥泄露 |
| `node scripts/site-smoke.mjs` | 访问四个用户指定站点，记录提取与定位结果 |
| `npm run test:live` | 显式使用本地配置验证真实模型，产生少量调用费用 |
| `npm run test:live-browser` | 在真实扩展中对公开网页提问，验证官方模型回答、引用与定位；先运行 test:live |

真实模型测试读取根目录的 `大模型地址和apikey.txt`（两行：接口地址、API Key），也可用环境变量 `READER_CREDENTIALS_FILE` 指定其他本地文件。该文件已加入忽略规则，构建过程不读取它，分享包采用文件白名单。`READER_TEST_MODEL` 可指定测试模型。不要把密钥提交到版本控制。

## 数据与限制

文档内容只有在用户主动使用时才提取。模型仅获得问题、有限历史、选区与必要片段；分批全文概括会发送全部已提取文字，并在界面明确提示。密钥仅在扩展可信上下文中读取，不传给 content script，不写入对话或调试日志。

首版不做 PDF、图片 OCR、图表视觉理解、跨网页集合、联网搜索、自动操作、同步与账号。图片较多的页面会提示未理解图片；iframe、Shadow DOM、扫描图片、懒加载但尚未出现在 DOM 的内容可能缺失。全文概括覆盖已提取文字，不代表识别了图片或整套网站。

自动化验证运行于 Linux Chromium；Windows Chrome 与 Edge 的安装、原生侧边栏入口仍应在实际设备复核。宇树站点在本测试环境返回访问拦截页，扩展会明确报错，未把该环境下的目标正文兼容性算作通过。详情见 [测试报告](docs/TEST_REPORT.md) 与 [已知限制](docs/KNOWN_LIMITATIONS.md)。

工程划分与边界见 [架构说明](docs/ARCHITECTURE.md)，后续版本见 [开发路线](docs/ROADMAP.md)。构建包包含 `THIRD_PARTY_LICENSES.txt`。
